RemoveBG — الاستوديو الاحترافي لتحرير الصور

هذه النسخة مخصصة للموقع الحالي الذي يستخدم قاعدة بيانات Supabase الموجودة بالفعل. لا تحتاج إلى وظائف خادمية أو مسارات API إضافية؛ الواجهة تتصل مباشرةً بـ Supabase وتستخدم مسار Pixelcut المباشر نفسه الموجود في النسخة الأصلية التي كانت تعمل.

ما تم الحفاظ عليه وتعديله
- جميع صفحات الاستوديو الحالية: المحرر، مكتبة الأصول، الحساب الشخصي، السجل ولوحة الإدارة.
- 32 فلترًا، و15 تحويلًا فنيًا محليًا، و13 مؤثرًا بصريًا قابلًا للتصدير، و18 إطارًا.
- صور معاينة محلية منفصلة للخدمات داخل مجلد images مباشرةً؛ لذلك تظهر البطاقات حتى عند تعذر تحميل مصدر خارجي.
- معاينات الفلاتر تُبنى من الصورة التي يرفعها المستخدم بدل رسومات تجريبية عامة.
- بعد رفع الصورة، تفتح لوحة التعديلات الأساسية تلقائيًا، وتبقى لوحة الفلاتر والتحويلات متاحة من شريط الأدوات.
- اختيار خلفية من مكتبة الأصول أو رفع خلفية جديدة يشغّل إزالة الخلفية تلقائيًا مرة واحدة، ثم يركّب الخلفية المختارة خلف العنصر.
- عمليات تغيير الخلفية اللاحقة لا تعيد إزالة الخلفية بعد نجاح الفصل.
- استعادة تكامل إزالة الخلفية المباشر المستخدم في نسخة المشروع الأصلية: https://api2.pixelcut.app/image/matte/v1 مع حقول FormData نفسها ورأس x-client-version.
- تظل الملفات الأصلية والنتائج وسجل العمليات داخل Supabase الحالي عبر الجداول والمسارات الموجودة في المشروع؛ لم تتم إضافة جداول أو قواعد بيانات جديدة.
- التوقيع يستخدم خط Aref Ruqaa Ink ويثبت نسبيًا في الركن السفلي الأيمن. لا يمكن سحبه أو نسخه أو تغيير موضعه، ويمكن تغيير النص واللون والحجم والشفافية أو إخفاؤه وحذفه.
- جميع إعدادات Supabase الحالية محفوظة في config.js.

التشغيل والنشر
1. فك ضغط الأرشيف.
2. ارفع محتويات المجلد إلى جذر مستودع الموقع الحالي مع الحفاظ على مجلد images الموجود مباشرة بجوار index.html.
3. انشر الموقع بالطريقة المعتادة لدى مزود الاستضافة الذي تستخدمه حاليًا. المشروع ثابت (HTML/CSS/JavaScript) ولا يتطلب وظائف خادمية أو مسارات API جديدة.
4. لا تغيّر Supabase URL أو المفتاح العام أو اسم bucket في config.js ما دامت إعدادات مشروعك الحالي صحيحة.
5. تأكد من أن سياسة Storage تسمح للمستخدم المسجل برفع الملفات داخل مجلده وقراءتها، وأن RPC create_removebg_operation موجودة كما في قاعدة البيانات الحالية.

إزالة الخلفية
- يستخدم الموقع نقطة Pixelcut المباشرة نفسها في النسخة الأصلية: PIXELCUT_DIRECT في config.js.
- لا يحتاج هذا الإصدار إلى مفتاح خادم إضافي أو مسار خادمي لإزالة الخلفية.
- إذا تغيّر سلوك نقطة Pixelcut المباشرة أو قيود CORS لدى مزود الخدمة، قد تتأثر المعالجة داخل المتصفح؛ لذلك أبقينا طريقة الطلب والحقول ورأس العميل مطابقة للنسخة القديمة التي أبلغت أنها كانت تعمل.
- بعد نجاح المعالجة، تُرفع النسخة الأصلية والنتيجة إلى Supabase ويُنشأ سجل العملية باستخدام الدالة الموجودة في قاعدة البيانات.
- إذا نجحت إزالة الخلفية وفشل حفظ السجل، تبقى النتيجة في المحرر وتظهر رسالة مستقلة بدل إلغاء نتيجة المعالجة.
- الحد اليومي والخطة وحالة الحساب ما زالت تُقرأ من profiles ويُسجل الاستخدام في operations كما في المشروع الحالي.

مكتبة الأصول
- 18 خلفية جاهزة و36 خلفية خارجية مختارة، مع 14 تراكبًا ضوئيًا وملمسيًا.

- OpenMoji: https://openmoji.org/ — تُحمّل المكتبة الكاملة عند الطلب مع تصفح وبحث وفئات ومفضلة؛ الرسومات بترخيص CC BY-SA 4.0، ويجب الاحتفاظ ببيانات النسب والترخيص.
- Unsplash: https://unsplash.com/license — راجع شروط الصور قبل الاستخدام التجاري أو إعادة النشر.
- لا يستخدم تحميل الأصول أي مسار /api أو وسيط استضافة. تُحمّل الموارد مباشرةً مع CORS؛ إذا كان مصدر بعينه يمنع CORS فلن يستطيع المتصفح دمجه في Canvas أو تصديره. في هذه الحالة اختر نتيجة أخرى أو ارفع الملف من جهازك.

ملاحظات
- لا توجد ملفات وظائف خادمية أو إعدادات استضافة إضافية في هذا الأرشيف.
- تفضيلات الحساب والمفضلة والملصقات الأخيرة تعتمد على التخزين المحلي للمتصفح حيث كانت كذلك في النسخة السابقة.
- اجتازت ملفات JavaScript فحص الصياغة، وتم فحص HTML وCSS والمراجع المحلية. لم تُنفذ طلبات حية إلى Pixelcut أو Supabase من بيئة البناء، لذلك يجب اختبار تسجيل الدخول والرفع وإزالة الخلفية على الموقع المنشور.


ملاحظة التحويلات الفنية: أنماط الأنمي والمانجا والكرتون والرسم المائي وغيرها معالجة Canvas محلية قابلة للتصدير، وليست نماذج توليد ذكاء اصطناعي. التحويل التوليدي الحقيقي يحتاج إلى خدمة ذكاء اصطناعي خارجية ومفتاح API محفوظ على خادم آمن.
