تقرير نسخة Cloudflare Pages

- أزيلت ملفات Vercel ومجلد api الخاص به من الحزمة.
- بقيت Pages Function فقط في functions/api/nanobanana.js بجذر المستودع.
- أضيف build.mjs لتجهيز الملفات العامة داخل dist، مع إبقاء functions خارج dist.
- أصبح مسار الواجهة نسبيًا /api/nanobanana، لذلك يعمل تلقائيًا على النطاق الفرعي المرتبط بمشروع Pages.
- أضيف GET health check يعيد JSON للتأكد من نشر الدالة، بينما يبقى POST مخصصًا للتحرير بعد التحقق من المستخدم.
- لم يتم تعديل config.js أو بيانات Supabase الحالية.
- يلزم ضبط Pages على Build command: npm run build وBuild output directory: dist ثم النشر عبر Git integration.
- يلزم التحقق من Compatibility date وnodejs_compat في إعدادات Functions.

الاختبارات المحلية: بناء dist، مراجعة ملفات الواجهة والصور، فحص الصياغة، والتحقق من وجود Pages Function في المسار الصحيح.
الاختبارات غير المنفذة: ربط النطاق الفرعي بالحساب الفعلي، نشر Cloudflare من حساب المستخدم، اتصال Pixhost الفعلي، واستدعاء Nano Banana الحقيقي.
